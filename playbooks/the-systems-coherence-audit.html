Why this playbook exists
The other eight layers can be rebuilt correctly on paper and still fail in practice if the systems underneath can't run them. A new pricing model, a new comp plan, and a new metering approach all depend on the same underlying data being calibrated and consistent across CRM, CPQ, billing, and analytics — because it's that per-customer calibration, not any single tool, that becomes genuinely difficult for a competitor to copy. A fragmented stack doesn't just create friction, it silently reverts every other layer back to what the old systems know how to do.
Two ways commercial systems are structured, compared

Only one of these can actually run a rebuilt commercial model rather than quietly reverting it.

Approach 1
Fragmented Stack
CRM, CPQ, billing, and analytics maintained as separate systems of record
Each tool is best-in-class for its own narrow job
Easier to swap out any one piece independently
No single, calibrated view of a customer across systems
New pricing, comp, or metering models get quietly reverted to what old systems can handle
Approach 2
Unified Calibration Layer
A consistent, per-customer data layer underneath CRM, CPQ, billing, and analytics
The hard-to-copy moat sits here, not in any single tool
Every other layer you rebuild actually holds, because the systems can run it
Requires sustained investment, not a one-off integration project
Needs a clear owner, or coherence quietly decays as new tools get added
Reality check
Integration Theater
Systems technically connected via APIs, but the underlying data isn't actually calibrated
Looks unified from an architecture diagram
Numbers still disagree between systems when anyone checks closely
The appearance of coherence delays the real fix

Five signals your systems are quietly blocking the model you've designed

Mark each one honestly against your current stack.

✓
The same customer's data disagrees across CRM, billing, and analytics when anyone checks closely
This is the clearest sign the underlying calibration doesn't exist yet, whatever the integration diagram suggests.
✓
A pricing, comp, or metering change has been scaled back because the systems couldn't support the original design
This is the failure mode in its most visible form: the commercial model gets quietly reverted to what the old systems already know how to do.
✓
Reporting a single customer's full picture requires manually reconciling exports from multiple systems
Manual reconciliation is a symptom of missing calibration, and it doesn't scale as the commercial model gets more complex.
✓
Systems are connected via integrations, but no one owns whether the underlying data is actually consistent
Integration Theater happens when connectivity is treated as equivalent to coherence — they are not the same thing.
✓
The per-customer calibration this stack could provide isn't treated as a competitive asset
This calibration, done well, is genuinely hard for a competitor to replicate — treating it as plumbing rather than a moat leaves that advantage unbuilt.

The 30-day action plan
Week 1
Pick one customer and pull their data from every system. Compare CRM, CPQ, billing, and analytics side by side and note every discrepancy.
Week 2
Trace one discrepancy to its root cause. Find out where in the pipeline the numbers actually diverge, not just that they do.
Week 3
Identify what this blocks. Map which planned or wished-for pricing, comp, or metering changes depend on this data being coherent.
Week 4
Assign ownership of calibration as an ongoing responsibility. This isn't a one-time project — someone needs to own keeping systems coherent as new tools and models get added.
